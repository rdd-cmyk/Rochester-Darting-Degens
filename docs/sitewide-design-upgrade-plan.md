## 1. Objective and scope

Bring every website route and shared interface up to the quality, style, clarity, responsiveness, and usability of Advanced Statistics while preserving existing functionality and data meanings. Establish reusable design foundations so later changes stay consistent.

The owner started the site-wide implementation goal after reviewing the plan and design preferences. Track progress against the full completion criteria below.

Owner-confirmed direction (2026-09-26): Home remains leaderboard-first, with the overall leaderboard as its first substantive content after a compact header. Summer decorations remain optional and restrained, with the toggle and saved preference preserved. No change to the first-visit Summer default was requested.

In scope once the user starts the migration: design-token consolidation, shared presentational components, page hierarchy, navigation, forms, tables, responsive behavior, theme consistency, accessible interactions, interface copy, and visible loading/error/empty/success states. Include interface defects uncovered in those touched areas, such as incomplete field labels or the known Summer-toggle hydration mismatch.

Outside this goal: new statistics formulas, new metrics, League Night Mode, rematch shortcuts, draft autosave, imports/OCR, new scoring models, schema migrations, hosted database writes for testing, auth/RLS policy changes, dependency modernization, and production deployment. Preserve existing save behavior and authorization; backend transaction redesign is separate work. Do not silently enlarge the task because the statistics roadmap contains later features.

## 3. Evidence and initial findings

The source tree contains 11 page routes, one API route, shared navigation/layout, a seasonal overlay, reusable player links, and the statistics components. Re-enumerate the actual implementation branch at startup; this inventory is a baseline, not permission to ignore subsequently added routes.

Following owner sign-in on 2026-09-26, the live authenticated `/stats` dashboard was visually reviewed in dark appearance at the available desktop viewport, 1440px desktop width, and 390px mobile width. The review covered All/All/3+, 501/All/3+ with no eligible players, and 501/All/1+ with populated cards, chart, leaderboard and consistency panels. Exact rating history was opened using the keyboard. The signed-in Matches page was also visually inspected; its form was not submitted. Earlier review covered the authentication-error state and Home's structure. Light theme and other unexercised states remain source-reviewed only. Existing browser QA scripts provide local synthetic scenarios, but their historical results have not been rerun for this preparation. Live visual review does not replace M1's reproducible baselines or M8's acceptance gates.

Concrete inconsistencies to resolve:

- `/stats` uses a 1240px themed shell; older pages use a 1100px shell or inline widths and their own spacing.
- Shared navigation is charcoal with unrelated button styling; the footer has fixed gray text. Neither fully follows the reference palette.
- Older pages contain repeated inline blue/gray colors, action styles, form rows, and table formatting.
- The home page leads into five dense leaderboard sections; useful hierarchy can improve without dropping any of them.
- Match entry contains visible text spans beside controls that need programmatically associated labels.
- Account pages and My Profile need consistent state panels, form treatments, and dark-theme colors.
- The font variables are named Geist but currently resolve to Arial/Courier New. Do not accidentally introduce a font migration.
- The source QA notes a Summer-Off/full-reload hydration mismatch. Reproduce on the current baseline before fixing it in shared-shell work.
- The home introduction includes a dated event announcement. Verify its relevance; do not fabricate replacement event details.
- Mobile chart/table overflow is contained, but the initial view gives little explanation that key content lies to the right. Add an explicit scrolling cue and test access to the final columns/endpoints.
- Equal ratings in the filtered 501 chart produce overlapping endpoint labels. Include ties and near-ties in chart-label acceptance while preserving the real data geometry.
- Consistency cards show a prominent median without naming it. Add an explicit metric label and keep sample counts adjacent; use small-sample fixtures to avoid overstating confidence.
- The 501 filter at 3+ can show matches analyzed but no eligible players. Preserve this distinction and test that reducing the threshold restores results without resetting the other filters.
