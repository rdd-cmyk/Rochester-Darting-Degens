## Exact local release input and preservation

The fixed [release environment](../../scripts/release-environment.mjs) lists
eleven ordered SQL inputs. The [rehearsal](../../scripts/release-sql.mjs)
starts from the checked-in existing-schema baseline, inserts a fictional
complete legacy match/profile/participant and snapshots their original fields
before any release SQL. Every input was deliberately interrupted immediately
before COMMIT on an isolated staged database. A full application-schema/data
digest matched before and after each interruption; the exact input was then
applied. Blind replay was accepted only where designed and otherwise refused
without state change. The old split-write client remained usable at the first
ten boundaries and was denied after the staged enforcement input. Before the
fixture membership backfill, an existing identity was denied under the new
admission policy; explicit membership admitted it afterward. There is no
automatic admission of all Auth users. The original complete row values,
relationships, historical nulls and default meanings survived. The combined
pgTAP suites passed **442 assertions**, including final grants, RLS and RPC
boundaries. On the actual app database, nine original-row assertions also
passed after feature tests had added new fictional data.

Canonical-LF SHA-256 values for this exact ordered local input are recorded in
the ignored `.local/release-w3/combined-sql.json`; they can be regenerated by
`node scripts/release-local.mjs rehearse`. The source itself remains in
`supabase/pending/` and `supabase/tests/fixtures/`, not migrations. This
synthetic order and timing are **not** a production migration-history or
maintenance-window decision. Real conflicts, account lists and row volumes
belong to W4/W5.

On a clone of the upgraded staged database, a held lock made the deferred
statistics validation time out at about 2.1 seconds, then a retry validated
all four constraints. Terminating a backend before COMMIT left no partial
row; the next exact operation created one. These small fictional timings do
not estimate a production lock or restore window. The ignored local details
are `.local/release-w3/resilience.json`.
